# 08 Alpha101 / Alpha191

公式来自内置的 popbo 实现（`efficient_cryptos/factors/popbo_alphas/`），在本仓库的 30m 截面上计算。

## 历史回测

```bash
cargo build --release --manifest-path rust_backtest/Cargo.toml

python scripts/08_alpha/sweep_alpha_test.py \
  --data-dir data --symbols $SYMBOLS \
  --families alpha101,alpha191 --alphas all \
  --interval 30m --horizon 1 --days 1100 \
  --test-start 2026-01-01 --test-end 2026-10-01 \
  --rebalance-hours 1,2,4,8,12,24 \
  --long-percent 10 --short-percent 10 --gross-leverage 1 \
  --out-dir outputs/alpha_sweep
```

流程是：先计算每个 Alpha 的 prediction，然后用和 DPSK 因子**同一个** Rust 核心回测，十层分层定义、手续费、冲击滑点、按真实结算时间收取的资金费、杠杆处理都相同。

输出：
- `<周期>/<alpha>.metrics.json / layers.csv / timeseries.csv`；
- 汇总表 `alpha_sweep_test.csv`；
- 按 `--min-pnl-pct` 和 `--min-abs-q10-pct` 筛出的 `alpha_sweep_test_selected.csv`；
- `--keep-artifacts` 会保留每个 Alpha 的 prediction CSV。

> **这里的参数名 `--test-start`/`--test-end` 只表示回测区间。** 如果在这段区间上筛选 Alpha，它就成了训练期，不能再把结果当作样本外表现。正式流程应该先在较早的区间筛选，再在之后的区间验证（见 04）。

结果目录可以直接用 `scripts/04_selection/scan_rust_factors.py` 扫描。

## 实盘

```bash
python scripts/06_live/run_live.py --alpha-config config/default.yaml \
  --rebalance-hours 24 --poll-seconds 60 --output outputs/alpha_dry_run --network mainnet
```

配置在 `config/default.yaml` 的 `alpha_live` 段：

| 字段 | 含义 |
|---|---|
| `family`、`alpha` | 使用哪个 Alpha，例如 `alpha101` / `alpha020` |
| `direction_sign` | `1` 表示因子值越高越做多，`-1` 相反 |
| `bar_min` | 计算用的 bar 长度（分钟） |
| `n_long`、`n_short` | 多空各选几个币 |
| `min_assets_per_bar` | 最新 bar 上有效币种少于这个数时，本轮不出信号 |
| `history_bars` | 拉取多少根历史 bar |
| `sizing` | `inverse_vol`（默认，按波动率倒数定仓）或 `equal_weight` |
| `symbols` | 指定币池；为空时用 `universe` 段的流动性 Top-N |

另外 `portfolio` 段设置目标波动率、总杠杆上限和单币权重上限。

扫描器每根 bar 只运行一次。它拉取币池的 1m 历史，算出 Alpha 并按自己的规则定仓，然后把目标交给风控引擎。如果最新 bar 上有效币种太少，这一轮报错并保留原仓位，不会用过期的 K 线下单。
