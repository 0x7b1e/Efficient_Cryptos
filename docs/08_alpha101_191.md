# 08 Alpha101 / Alpha191

Formulas come from the bundled popbo implementation (`efficient_cryptos/factors/popbo_alphas/`) and are computed on this repository's 30m cross-section.

## Historical backtest

```bash
cargo build --release --manifest-path rust_backtest/Cargo.toml

python scripts/08_alpha/sweep_alpha_test.py \
  --data-dir data --symbols $SYMBOLS \
  --families alpha101,alpha191 --alphas all \
  --interval 30m --horizon 1 --days 1100 \
  --test-start 2026-01-01 --test-end 2026-10-01 \
  --rebalance-hours 1,2,4,8,12,24 \
  --long-percent 10 --short-percent 10 --gross-leverage 1 \
  --out-dir outputs/alpha_sweep
```

The flow: first compute each Alpha's predictions, then backtest them with **the same** Rust core as the DPSK factors — the decile definition, fees, impact slippage, funding charged at actual settlement times and leverage handling are all identical.

Outputs:
- `<period>/<alpha>.metrics.json / layers.csv / timeseries.csv`;
- the summary table `alpha_sweep_test.csv`;
- `alpha_sweep_test_selected.csv`, filtered by `--min-pnl-pct` and `--min-abs-q10-pct`;
- `--keep-artifacts` keeps each Alpha's prediction CSV.

> **The argument names `--test-start`/`--test-end` here only denote the backtest range.** If you select Alphas on this range, it becomes a training period and the results can no longer be treated as out-of-sample performance. The proper flow is to select on an earlier range and validate on a later one (see 04).

The results directory can be scanned directly with `scripts/04_selection/scan_rust_factors.py`.

## Live trading

```bash
python scripts/06_live/run_live.py --alpha-config config/default.yaml \
  --rebalance-hours 24 --poll-seconds 60 --output outputs/alpha_dry_run --network mainnet
```

Configured in the `alpha_live` section of `config/default.yaml`:

| Field | Meaning |
|---|---|
| `family`, `alpha` | Which Alpha to use, e.g. `alpha101` / `alpha020` |
| `direction_sign` | `1` means a higher factor value goes more long, `-1` the opposite |
| `bar_min` | Bar length used for computation (minutes) |
| `n_long`, `n_short` | Number of symbols on each side |
| `min_assets_per_bar` | No signal this cycle if the latest bar has fewer valid symbols than this |
| `history_bars` | How many historical bars to fetch |
| `sizing` | `inverse_vol` (default, inverse-volatility sizing) or `equal_weight` |
| `symbols` | Explicit universe; when empty, the liquidity Top-N from the `universe` section is used |

The `portfolio` section additionally sets target volatility, the gross leverage cap and the per-symbol weight cap.

The scanner runs only once per bar. It fetches the universe's 1m history, computes the Alpha, sizes by its own rules, then hands the targets to the risk engine. If the latest bar has too few valid symbols, the cycle errors out and keeps existing positions, rather than trading on stale klines.
